## 0. Что есть сейчас (коротко)

Десктоп-приложение на PySide6 для генерации извещений на замену материалов.
Один главный экран с 3 вкладками + 10 диалогов. Всё на нативных виджетах Qt,
без кастомных стилей. Архитектура кода в целом чистая (MVC-подобное разделение
`models / stores / gui`), но UI-слой нарос органически — отсюда проблемы.

**Объём кода:**
- `app/gui/` — 13 файлов, ~270 КБ Python
- Самые тяжёлые: `changes_table_widget.py` (87 КБ), `replacement_sets_editor_widget.py` (65 КБ), `main_window.py` (44 КБ)
- Тестов: 2 файла (`test_document_load.py`, `test_numbering.py`)

**Меню:** Документ → Новый / Открыть; Данные → Импорт Парсинг.xlsx / Привязки деталей / Восстановление БД; Настройки → Настройки.

**Вкладки:**
1. **Реквизиты документа** — номер (MM-YY-NNN, авто), дата внедрения, срок действия (месяц), год для нумерации, причина.
2. **Изменения материалов** — выбор машин (галочки), поиск детали, выбор детали (autocomplete), 9 кнопок действий в одну строку, таблица 9 колонок.
3. **Наборы** — выбор детали, splitter: слева список пар наборов, справа редактор from/to.

**Нижние кнопки:** Сгенерировать документ / Добавить данные для доп. страницы / Очистить.

**Проблемы таблицы:**
- Колонка "Тип" всегда пустая — место потрачено впустую.
- "Страница" — визуально не сразу понятно зачем (нет tooltip).

- Нет возможности выделить несколько строк и применить операцию ко всем (bulk fill, bulk change).
- Цветовая подсветка только светло-голубая (доп. страницы) и светло-красная (запрет). Нет визуального разделения "есть история замен" / "нет истории".

### 1.4 Вкладка "Наборы" (`replacement_sets_editor_widget.py`, 65 КБ)

**Верх:**
- Label "Деталь:" + `part_combo` (autocomplete) + кнопка "Обновить".
- `part_usage_label` ("Последнее добавление в документ: …") — отличная идея, но используется редко.

**Splitter:**
- **Левая часть:** список пар наборов (`sets_table` — 6 колонок: Дата | Название | ID to | ID from | Кол-во from | Кол-во to) + кнопки "Новый" / "Копировать пару" / "Удалить пару".
- **Правая часть (редактор):**
  - QLineEdit для названия набора.
  - Кнопки "Отменить изменения" / "Сохранить" / "Сохранить и добавить".
  - Группа "до" (from): таблица + кнопки "Добавить новый" / "Выбрать из каталога" / "Удалить выбранные" / "Выбор замены".
  - Группа "после" (to): таблица + кнопки "Добавить новый" / "Выбрать из каталога" / "Удалить выбранные".
  - Низ: "Добавить деталь" / "Вынести в новый набор".

**Проблемы:**
- Две таблицы (from/to) — нет визуальной связи между строками (молчаливо "сопоставляются по индексу"). Пользователь не понимает какая строка к какой.
- Кнопка "Выбор замены" есть только для `from`, но не для `to` — непоследовательно.
- Кнопки "Добавить новый" vs "Выбрать из каталога" — длинные тексты, нет иконок.
- "Сохранить" и "Сохранить и добавить" рядом — легко промахнуться.

## 3. Что предлагаю — концепция

### 3.1 Принципы
- **Один экран — одна задача.** Сейчас вкладка "Изменения материалов" — это всё сразу.
- **Контекст всегда виден.** Доп. страницы, TKO, причина, запреты — не "глубоко в диалоге", а на глазах.
- **Bulk вместо клик-в-клик.** Массовое выделение и групповые операции.
- **Стиль — единый QSS.** Свой стиль вместо нативного. Темы light/dark.
- **Безопасные деструктивные операции** (удаление из БД, восстановление) — в отдельной панели "Администрирование" с подтверждением по паролю или хотя бы с 2-step confirm.
- **Прогресс виден.** Статус-бар внизу: машин / деталей / замен / запретов / последнее сохранение.

### 3.2 Целевая структура главного окна

```
┌─────────────────────────────────────────────────────────────────────┐
│ Меню: Документ | Данные | Справочник | Администрирование | Настройки │
├─────────────────────────────────────────────────────────────────────┤
│ Toolbar (иконки):                                                    │
│ [Новый][Открыть][Сохранить][Черновик: сохранён 14:38] ... | Поиск🔍 │
├──────────┬──────────────────────────────────────────────────────────┤
│ Sidebar  │ Содержимое документа — Wizard-стиль                      │
│ ─────    │ ─────                                                     │
│ 1. Шапка │  [Активная доп. страница: 1 | 2+ | 3+ | +Добавить]      │
│ 2. Мат.  │                                                          │
│ 3. Наборы│  <Здесь содержимое текущего шага>                         │
│ 4. Предп.│                                                          │
│          │                                                          │
├──────────┴──────────────────────────────────────────────────────────┤
│ Status bar: 3 детали | 2 машины | 1 замена | 0 запретов | БД OK     │
├─────────────────────────────────────────────────────────────────────┤
│ [Сгенерировать документ]              [Отмена] [Черновик] [Очистить]│
└─────────────────────────────────────────────────────────────────────┘
```

Wizard-стиль вместо вкладок:
1. **Шапка документа** — номер, дата, причина, TKO, машины.
2. **Материалы** — изменяемые позиции с галочками "Меняем" и предпросмотром до/после.
3. **Наборы** — управление наборами (бывшая вкладка 3).
4. **Предпросмотр** — что попадёт в Excel, сколько страниц, есть ли запреты, проверка валидации.

Слева — прогресс по шагам (зелёная/серая/красная иконка).

### 3.3 Конкретные изменения по экранам

#### Шаг 1 — Реквизиты (бывш. вкладка 1)
Добавить:
- Поле **TKO заключение** (textarea).
- Шаблоны причины замены (кнопка "📋 Шаблон" → выпадающий список: "Отсутствие материала", "Переход на аналог", "ТКО", "Прочее...").
- Бейдж статуса нумерации: "Номер будет: **ММ-ГГ-NNN** (свободно 245 из 999)" — пользователь видит что место есть.
- Автосохранение черновика (каждые 30 сек).

#### Шаг 2 — Материалы (бывш. вкладка 2)
Группировка кнопок в 3 панели:

```
┌─ Деталь ─────────────────────────────────────────────────┐
│ [Поиск детали: _________ 🔍]  [Выбрать из списка ▾]     │
│ Кнопка [+ Добавить деталь в документ]                     │
└──────────────────────────────────────────────────────────┘
┌─ Действия ───────────────────────────────────────────────┐
│ [📝 Создать деталь] [📋 Копировать] [✏️ Редактировать набор]│
└──────────────────────────────────────────────────────────┘
┌─ Управление (опасно) ────────────────────────────────────┐
│ [🗑 Удалить деталь] [🗑 Удалить строку] [⛔ Запреты…]     │
│ [⚠️ Удалить деталь из БД]                                │
└──────────────────────────────────────────────────────────┘
```

- Единое поле поиска вместо двух.
- Таблица: убрать пустую колонку "Тип", добавить колонку **"История"** (бейдж: есть/нет), расширить колонку "после" до автокомплита с историей + глобальным словарём.
- Кнопка **"⛔ Запреты…"** открывает панель запретов (см. ниже).
- Доп. страницы — через явный **breadcrumb-tabs** сверху таблицы: `[1] [2+] [3+] [+ Новая]`. Активная подсвечена, остальные кликабельны.
- Bulk-actions при выделении нескольких строк: "Отметить все как меняемые", "Очистить колонку после".

#### Шаг 3 — Наборы (бывш. вкладка 3)
- Визуализация from/to как **парных строк** (одна таблица с колонкой "Тип: до/после" и визуальной связью линиями).
- Или оставить две таблицы, но с **общим выделением строк** (выделил в "до" — подсветилось в "после").
- Иконки вместо текстов в кнопках.
- "Сохранить" сделать primary-кнопкой, "Сохранить и добавить" — secondary.

#### Шаг 4 — Предпросмотр (новый)
Перед генерацией показывает:
- Список деталей по страницам (1, 2+, 3+...).
- Какие материалы заменены, на что.
- Какие машины указаны.
- ⚠️ Список запрещённых замен с возможностью "Снять запрет" или "Убрать замену".
- Примерный размер итогового файла.

#### Панель запретов (новый)
Отдельный диалог/виджет:
- Таблица всех запретов с фильтрами.
- Причина запрета (опционально), кто поставил, когда.
- Действия: снять запрет, изменить причину, экспорт.

#### Настройки
Разбить на табы:
- **Общие** — папка сохранения, открывать ли файл после генерации, шаблоны причин.
- **Нумерация** — начальный номер, год по умолчанию, текущий счётчик по месяцам.
- **Хранилище** — путь к БД, политика бэкапов.
- **Внешний вид** — тема (light/dark/system), размер шрифта.

## 4. Что предлагаю по функциям (новое)

В порядке приоритета (что решает больше всего боли):

1. **Автосохранение черновика** — раз в 30 сек в `data/drafts/`. Восстановление при старте если черновик свежее последнего сохранённого документа.
2. **Статус-бар** — счётчики деталей/машин/замен/запретов, индикатор БД.
3. **Шаблоны причин замены** — настраиваемый список, дефолты "Отсутствие материала", "Переход на аналог", "ТКО".
4. **Bulk-операции** в таблице — выделение нескольких строк, массовый чек/анчек, массовая очистка "после".
5. **Горячие клавиши** — Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+G (генерация), Ctrl+Z/Y, F1 (справка).
6. **Панель запретов** (вынести из одной кнопки).
7. **Поле TKO заключения** в UI.
8. **Предпросмотр перед генерацией**.
9. **Темы** (light/dark/system).
10. **Журнал действий** (audit log) — кто что менял, можно откатить.
11. **Импорт/экспорт черновика** — JSON-снимок документа.
12. **Расширенный поиск** — по материалу, по истории замен, по номеру документа.
13. **Контекстное меню (правый клик)** в таблицах: копировать строку, дублировать, вставить.
